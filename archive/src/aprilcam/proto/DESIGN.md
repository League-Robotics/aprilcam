## 1. Purpose

The generated Python bindings for the AprilCam wire contract. This package is
*output, not source*: `aprilcam_pb2.py` and `aprilcam_pb2_grpc.py` are
regenerated by `scripts/compile_proto.py` from `proto/aprilcam.proto` (project
root). It exists as a package so every process — daemon, MCP server, client
library, CLI — imports message types from exactly one place. The boundary it
owns is the wire contract itself; nothing else defines message shapes.

## 2. Orientation

One source file, `proto/aprilcam.proto`, defines a single `AprilCam` gRPC
service (24 unary RPCs, no gRPC streaming) plus the binary stream messages
that are *not* gRPC responses but live in the same file so all types come
from one generated module. Streaming happens over separate sockets whose
endpoints are allocated by the `GetImageStream` / `GetTagStream` RPCs.

RPC groups: camera lifecycle (ListCameras, EnumerateCameras, OpenCamera,
CloseCamera, ReloadCalibration, Shutdown); one-shot queries (GetCameraInfo,
CaptureFrame, GetTags, WhereIs, GetObjects); stream endpoint allocation
(GetImageStream, GetTagStream); overlay push (PublishOverlay); file-proxy
blobs (Get/SetCameraConfig, Get/SetCalibration, Get/SetPaths,
ListPlayfields — opaque JSON strings in `JsonBlobReply`/`CameraJsonRequest`
so `to_dict`/`from_dict` helpers are reused unchanged on both sides); and
the mobile-tag registry (RegisterMobileTag, ClearMobileTags, ListMobileTags).

Stream wire format: every stream socket carries length-prefixed protobuf —
`[uint32 big-endian length][serialized message]` (see `struct.pack(">I", …)`
in `daemon/stream.py` / `client/stream.py`). Image sockets carry raw
`ImageFrame` messages (frame_id, timestamps, JPEG bytes, dimensions). Tag
sockets carry `StreamMessage`, a oneof multiplexing `TagFrame` and
`OverlayFrame`. `TagFrame` is the perception payload: tag records plus the
row-major 3×3 homography, playfield corners, field dims (cm), fps, and the
A1-centred `origin_x`/`origin_y` consumers use to invert the world transform.
`ListPlayfieldsResponse.boot_id` piggybacks daemon-restart detection on an
existing call.

## 3. Constraints and Invariants

- **NEVER hand-edit the generated files.** All changes go into
  `proto/aprilcam.proto`, then `python scripts/compile_proto.py`. The script
  also rewrites the generated absolute import to a relative one
  (`from . import aprilcam_pb2 …`) — a hand-run `protoc` without that fixup
  produces a package that fails to import.
- **Empty repeated fields are the "uncalibrated" signal** — `homography`
  empty means no calibration; `wx`/`wy` of 0 means uncalibrated on TagMsg.
  Consumers must check emptiness, not trust zeros as coordinates.
- **`CameraDevice.index` is UNSTABLE** (changes on replug); `enum` is the
  persistent user-facing handle. Never expose `index` as an identifier.
- **Origin convention rides in the frame** — `origin_x`/`origin_y` on
  TagFrame/TagFrameResponse are what overlay consumers must use; clients
  never derive the origin themselves (a past y-flip bug came from exactly
  that).
- **Proto3 field numbers are forever** — additions append new numbers;
  removals reserve, never reuse. Breaking this silently corrupts decoding
  for mixed-version daemon/client deployments (which are normal: Pi daemon,
  laptop clients).

## 4. Design

Blob-style config RPCs (opaque JSON strings rather than typed messages) are a
deliberate trade: the JSON schemas of `config.json` / `calibration.json` /
playfield definitions evolve in Python, and typed protos would need a
regeneration + redeploy on every schema tweak across every client. The oneof
`StreamMessage` on tag sockets exists so overlays can be pushed to viewers
without a second socket per camera. Binary streams live outside gRPC because
frame delivery wants bounded-queue drop semantics and unix-socket fan-out,
not HTTP/2 flow control.

## 5. Interfaces

### Exposes

- `aprilcam.proto.aprilcam_pb2` — all message classes (TagMsg, TagFrame,
  ImageFrame, StreamMessage, OverlayFrame/OverlayElement, JsonBlobReply,
  CameraJsonRequest, MobileTagSpec, Where*, …).
- `aprilcam.proto.aprilcam_pb2_grpc` — `AprilCamStub` (clients),
  `AprilCamServicer` + `add_AprilCamServicer_to_server` (daemon).
- The contract itself: 24 unary RPCs as listed in §2; stream framing
  `[uint32 BE length][protobuf]`; raw `ImageFrame` on image sockets,
  `StreamMessage(TagFrame|OverlayFrame)` on tag sockets.

### Consumes

- `proto/aprilcam.proto` (the single source of truth) via
  `scripts/compile_proto.py` (grpc_tools.protoc + import fixup). Runtime:
  `protobuf`, `grpcio`.

## 6. Open Questions / Known Limitations

- **v2 extends the contract** with the deskewed-playfield stream, a
  `Calibrate` RPC (daemon-side calibration), `SetPlayfield`/`GetPlayfield`
  whole-document config, and `ResetCameraConfig` (spec §4.1, §4.4, §4.11).
- **v2 removes** `PublishOverlay` + `OverlayFrame`/`OverlayElement` (drawing
  becomes a client-side library, decision §9.2) and the `GetPaths`/`SetPaths`
  file-proxy RPCs (paths-as-a-service dropped, spec §6). `StreamMessage`
  likely collapses to TagFrame-only; keep the oneof wrapper for forward
  compatibility of the framing.
- **The blob RPCs carry no schema version**, so daemon and client must agree
  on JSON shape by deployment discipline alone. Whole-document semantics in
  v2 (spec §2.3) keeps this survivable; a version field is worth considering
  when the v2 config service lands.
